# LanDict 背单词 V7 预览说明

本轮改动：**↑ 改成「加入生词本」**，原来的「不再出现」挪到**双击 →**；提示行按
「双击 ← / 空格 / 双击 →」重排成一行；小结增加第五个统计。
仍然没有写任何产品代码，`src/` 未改动。

## 学习会话底部现在长这样

```
              ↑ 加入生词本              ← 与下面三个键同一种按钮形式，仍在上面
    ← 不认识   ↓ 不确定   → 认识
   双击 ← 返回上一个单词   空格 发音   双击 → 不再出现
```

提示行三项同排，中间是空格发音，两侧各是一个双击手势。

### 四个键各自做什么

| 键 | 单击 | 双击 |
| --- | --- | --- |
| ← | 不认识（释义态是"回到卡片重答"） | **返回上一个单词** |
| ↓ | 不确定（释义态是"记错了"） | — |
| → | 认识（释义态是"下一个单词"） | **不再出现本单词** |
| ↑ | **加入生词本** | — |

**「加入生词本」按的是"收藏标记"模型**：把这个词加进生词本、跳过它进入下一个词，
**不展开释义、也不改记忆档位**。理由是它和「不认识 / 不确定 / 认识」不是一类动作——
那三个是给这个词的掌握程度打分，而 ↑ 是"这个词对我重要，先收起来"。
生词本本身也是背单词的一个来源，所以这个词之后会从生词本那条线再出现。

如果你希望按 ↑ 之后也展开释义，或者顺便按「不确定」记档（这样它会更早回到复习队列），
告诉我，改起来各是几行。

**「不再出现」挪到双击 →**：单击 → 仍然是最常用的「认识 / 下一个」，双击才把词永久移出词库。
放在双击里也顺便降低了误触代价——这个动作是不可逆的，原来一颗键直接按下去就没了。

小结页因此有五个统计：认识 / 不确定 / 不认识 / 加生词本 / 不再出现。

## 单击 / 双击怎么区分

两个方向键各记一个时间标志（`state.lastLeftAt`、`state.lastRightAt`）。按下时如果距离
上一次不足 **300ms**，就判定为双击；否则先按单击执行，并记下这次的时间。

**为什么不是"等 300ms 再执行单击"**：那样每次单击都要等，整个背单词过程都会变钝。
现在的做法是单击立刻生效，双击时再把那一次撤回。代价是双击时画面会闪一下（约一两百毫秒）。
如果你更在意"绝不闪"，我可以改成延迟单击，但每次单击都会有 300ms 迟滞。

双击的两个动作分别落在哪：

| 当前在哪 | 双击 ← | 双击 → |
| --- | --- | --- |
| 第 3 词的卡片态 | 回到第 2 词的卡片态 | 第 3 词标为不再出现，进到第 4 词 |
| 第 3 词的释义态 | 撤销第 3 词的判定，回到第 2 词的卡片态 | 第 3 词标为不再出现，进到第 4 词 |
| 第 1 词 | 不越界，原地不动 | 第 1 词标为不再出现 |

两种双击都会先把单击那一步撤回（"认识"或"下一个"），所以语义始终是"作用在这张卡对应的那个词上"。
鼠标点按钮**不**触发双击逻辑——你说的左键、右键都是指方向键。

## 这一轮修掉的两个记账 bug

为了实现"返回上一个单词"，每答一次会压一条记录（`state.history`），撤销和回退都靠它。
写这个的过程中发现原来有两处记账不对：

1. **「记错了」被当成新的一步**。原来在释义页按 ↓ 会新压一条记录，于是同一个词有两条记录，
   "退回上一个单词"退回两级还停在同一个词上，统计和队列长度也会对不上。现在「记错了」
   是**改写当前这条记录**（不确定 → 不认识，认识 → 不认识），不新增记录；连按多次也不会重复计数。
2. **在释义页按 ↑ 会残留一次"认识"**。原来先记了"认识"，再按 ↑ 移出，那条"认识"还留在统计里。
   现在移出会先把这次判定撤掉，这个词只留一条"已移出"的记录。

顺便确认了这几个不变量：一路双击退回起点后，统计全部归零、词库队列恢复原长、记录清空。

## 二、会话页现在怎么排的

三段式，和上一版一样保证底部按钮不动：

| 段 | 内容 | 行为 |
| --- | --- | --- |
| 顶部 | 退出、第 N / 总数、进度条、当前内容名 | 固定高度 |
| 中间 | 单词 + 音标 + 释义 | 整体在中间区域**垂直居中** |
| 底部 | 太简单按钮、三个操作键、按键提示 | 固定高度，永不移动 |

中间区域的实现：`.study-body` 是 flex 容器，`.study-group` 用 `margin:auto` 居中。
卡片态只有单词，单词就在中间；答完题后释义区用 `max-height` 从 0 展开到 44vh，
整组高度变大但依然居中，所以**单词是平滑往上移，释义在它下面展开，底部按钮不动**。

用 `margin:auto` 而不是 `justify-content:center`，是因为窗口很矮、内容溢出时前者不会把顶部裁掉。

### 词库进度的显示（本轮新增）

需求是"一眼看出哪些词库背过、哪些没背"，而且不用数字。这里有一个绕不开的物理事实：

| 词库 | 已背 / 总数 | 比例 | 在 100px 宽的按钮上 |
| --- | --- | --- | --- |
| 四级 | 128 / 3,849 | 3.3% | 约 **3 像素**，等于看不见 |
| 考研 | 3,120 / 4,801 | 65% | 约 65 像素，很清楚 |
| 高考 | 3,677 / 3,677 | 100% | 整条填满 |

所以比例条对"刚开始背的大词库"几乎没有信息量，这不是画法问题，是尺度问题。

**最终选定的画法是「底部细条」**：按钮底部 3px 的轨道，绿色（`--status-mastered`）
填到哪算哪，没开始的只留一条空轨道（`--border-soft`）。文字区域完全干净，
一行扫过去也能看出谁有进度。另外两种（浅绿底色填充、三色状态圆点）已经删掉。

两个兜底保留：

- **只要不是 0%，就至少画 5px**，让"已经开始"这件事永远看得见（3.3% 的四级因此有一条细边）。
- **精确数字放在分区标题右边**，跟着选中的那个库走（`四级词库 · 已学 128 / 3,849 · 还剩 3,721 条`），
  按你的要求没有把百分比写在按钮上。鼠标停在按钮上会有一行提示给出精确百分比，觉得多余可以去掉。

进度口径统一用「**背过的词数 / 总数**」（生词本用「学习中 + 已掌握」，也就是 74 / 86）。
如果更想看"真正掌握"的比例，把 `learned` 换成 `mastered` 即可，但数字会更小、条会更短。

### 三套主题的适配

你软件有三套主题（`blue` / `lime` / `black`，默认 blue，在设置页切换，写入
`document.documentElement.dataset.theme`）。这一版把三套都适配了：

做法是让预览的变量**与 `tokens.css` 同名同值**（`--bg-app`、`--bg-surface`、`--bg-soft`、
`--bg-active`、`--blue-primary`、`--border-soft`、`--text-primary/secondary/muted`、
`--status-pending/learning/mastered` 及其 `-surface`、`--interactive-focus`、
`--interactive-on-primary`、`--primary-gradient`、`--surface-content`、`--shadow-card/hover`），
主题块直接照抄 `tokens.css`；预览内部那些短名字（`--bg`、`--surface`、`--accent`、`--green`…）
只写一次，用 `var()` 指向它们，所以换主题时自动跟着变。

核对结果：三套主题共 65 个变量逐个比对，全部一致（其中 4 项只是 `#fff` 与 `#ffffff`、
渐变里逗号空格的写法差异，颜色值相同）。

顺带修了两处只有深色主题才暴露的问题：

- 主按钮原来硬写 `color:#fff`，深色主题里按钮是浅色渐变，白字会看不清；改成
  `var(--interactive-on-primary)`（深色主题里是 `#142031`），并按 tokens.css 换成
  `background: var(--primary-gradient)`。
- 内容区补上 `background: var(--surface-content)`，深色主题下才是 `rgb(17 23 33 / 80%)`。

预览底部留了一条「预览用 · 主题」开关方便你当场切换。**它只存在于预览里**，不占应用界面——
侧栏那张主题卡片是按你上次的要求删掉的。你要是连这条也不想要，说一声就去掉。

## 四、逾期规则

复习队列取的是**下次复习时间 ≤ 今天的全部条目**。隔了几天没学，昨天、前天、上个月到期的
都会一起排进今天，不会消失。界面上因此这样写：

- 复习卡主数字改成「18 条 · 待复习」，下面的小字注明「其中 12 条是之前积压的」。
- 底部今日行写成「复习 0 / 18（含积压 12）」。
- 复习节奏面板底部加了一段说明，解释为什么这个数字有时会突然变大。

如果积压为 0，小字改成「都是今天刚到期」；一条都没有时提示先去背新词。

## 七、视觉依据

### 字体（V4 修正）

上一版写错了字体，这一版照 `src/styles/globals.css` 原样对齐：

```css
@font-face {
  font-family: "Noto Sans SC";
  src: url("../assets/fonts/NotoSansSC-VF.ttf") format("truetype");
  font-weight: 400 700;
  font-display: swap;
}
:root { font-family: "Noto Sans SC", sans-serif; font-synthesis: none; }
body  { font: 400 16px/1.5 "Noto Sans SC", sans-serif; }
button { font-weight: 500; }
h1..h6, strong, b { font-weight: 700; }
```

三条要点：字体名必须叫 `"Noto Sans SC"`（和 `--font-family-sans` 一致，否则回退到雅黑）；
可变字体的字重范围只有 **400–700**，所以全页只用 **400 / 500 / 700** 三档，不用
580、650、730 这类中间值，否则浏览器会合成字重；`font-synthesis: none` 也要跟着开。

### 字号层级

全部使用 `tokens.css` 里的 `--type-*`，没有一处硬编码 px：

| Token | 值 | 本页用在 |
| --- | --- | --- |
| `--type-page-title` | 36px | 页面标题「背单词」、两个模式卡的大数字 |
| `--type-word-title` | 40px | 会话里的单词 |
| `--type-page-title-compact` | 28px | 本轮小结标题 |
| `--type-card-title` | 20px | 「学习内容」、卡片标题、释义正文、小结数字 |
| `--type-body` | 16px | 正文、导航项、词库 chip、开始按钮、三个操作键 |
| `--type-secondary` | 14px | 辅助文字、音标、例句中文、搭配、档位表 |
| `--type-muted` | 12px | 弱信息、进度文字、按键提示、标签 |
| `--font-size-xs` | 11px | 音标里的 UK / US 角标、键盘按键 |

### 发音（2026-10-14 补充）

卡片上的 UK / US 两行走**应用既有的发音服务**，不是自己拼的：

| | 音标 | 音频 |
| --- | --- | --- |
| UK | 牛津 mdx 英式音标 | 免费英式音频（dictionaryapi）→ **有道真人录音** → 系统语音 |
| US | 牛津 mdx 美式音标 | **韦氏音频** → 有道真人录音 → 免费美式音频 → 系统语音 |

**有道这一路是怎么来的**（2026-10-14 第三次补充）：英式以前常常落到系统语音，因为免费的英式音源覆盖太差。
查过三条路：本地牛津 mdd 里只有 208 个音标字体图标、本地韦氏 mdd 里 1407 个全是图片，都没有音频；
牛津官网的 mp3 路径带 `_3`、`_rr` 这种编号（`government__gb_3.mp3`），**猜不出来**，必须先抓词条页；
最后用的是有道的公开接口 `https://dict.youdao.com/dictvoice?audio=<word>&type=<1|2>`——
官方 JSON 里写着 `ukspeech` 对应 `type=1`、`usspeech` 对应 `type=2`，不需要 key、也不用抓网页，
真人录音、短语也读得出来（`take sth into account` 有音频）。代价是多了一个第三方来源，个人自用没问题。

两个细节：牛津对美式只标「与英式不同的那半截」时（`government` 的 `/-vərn-/`），发音服务会把美式音标
退回成英式那一份完整音标，界面不会出现半截音标；音标来源和音频来源写在按钮的 title 上
（「牛津音标 · 韦氏美式发音」）。韦氏给的是重拼写法不是 IPA，所以只用它的音频、不用它的音标。

**展开释义时自动读一遍**：`认识 / 不确定 / 不认识` 让释义卡出现时自动念这个词，口音跟设置页的
朗读口音走，有音频放音频、没有用系统语音；收起释义或换到下一个词时会把声音停掉。
空格键仍然手动读（UK），点 UK / US 则按那一路的来源读。

### 发音不等网络（2026-10-14 第二次补充）

第一版的自动朗读是"要读的时候才去下载音频"，于是网络一慢就出现「释义已经翻出来了，声音还没响」。
现在 `src/features/study/studySpeech.ts` 只管三条规矩，各有一组单测：

1. **预热**：卡片资料一到（含音频地址）就建好音频元素让它自己下着，同一个地址只建一个；
2. **自动朗读**：要读的那一刻，音频已经能播（`readyState ≥ 2`）就放音频，否则**立刻**用系统语音——
   实测从"点认识"到出声 2–4ms，不会再为等网络而不出声；
3. **手点 UK / US**：先试音频，`900ms` 还没起播就改用系统语音；`play()` 被拒（自动播放策略）也会补系统语音。

口音按设置页的朗读口音选对应的那一路音频（英式免费音频 / 韦氏美式音频）；这个口音没有音频时直接系统语音。
停声：收起释义、换到下一个词都会 `pause()` 并把语音 `cancel()`。

实测（无头 Chrome，1440×900）：

| 场景 | 结果 |
| --- | --- |
| 朗读口音 = 英式，该词没有英式音频 | 4ms 内系统语音念出来 |
| 朗读口音 = 美式，韦氏音频已在卡片加载时预热 | 直接播放 `.../prons/en/us/mp3/c/centur02.mp3`，不念系统语音 |

### 美式音标：牛津优先，有道补半截（2026-10-14 第四次补充）

牛津对美式常常只印"和英式不同的那一段"（`government` 的 `/-vərn-/`），本地那份 mdx 存的就是这个省略写法，
所以屏幕上会出现"美式音标和英式一样、少了那个 r"。统计了 60 个四级词：
**美式完整 93%、只有半截 3%、空的 3%**——所以没有"美式全部换成第三方"，只在这 3%~6% 时补一次。

| 音标 | 来源顺序 |
| --- | --- |
| 英式 | 牛津（不动） |
| 美式 | 牛津完整 → **有道**（只在半截/空缺时）→ 维基等在线来源 → 退回英式那一份 |

有道的接口没有 CORS 头、带 Origin 直接 403，浏览器连不上，所以两边各加了一条中转：
开发版 `vite.config.ts` 里的 `/api/youdao-ipa`（带内存缓存），桌面版 `src-tauri` 的 `youdao_ipa` 命令。
实测一组四级新词（20 个）只有 3 个词问了有道（`government`、`interest`、`local`），其余 17 个用本地牛津。

顺手修掉一个显示 bug：服务给的音标自带斜杠，卡片又画了一对，于是显示成 `//ˈsɪstəm//`；
现在卡片自己负责那两个斜杠，服务那一层统一保留 `/…/` 写法（查词页直接用它，不受影响）。

浮窗也接上了共享发音链路，所以**所有界面**的英式发音现在都是"免费英式音频 → 有道真人录音 → 系统语音"：
背单词卡片、查词页、生词本、阅读页划词、鼠标取词浮窗。

### 两处按用户要求偏离预览（2026-10-14 第五次补充）

- **背新单词的图标换成字母 W**（Word）：预览里是"气泡加箭头"的图标，用户觉得丑，改用同一块浅蓝圆角底 + 20px 粗体 W。
- **词组库还没有释义**，正在解决，调查数据先记在这里。词组库里每一条能在本地牛津拿到中文释义的比例：

| 词组库 | 条数 | 能拿到中文释义 |
| --- | --- | --- |
| 固定习语 idiom | 3,091 | **100%** |
| 多词词条 multiword | 7,250 | **89%** |
| 常见搭配 colloc | 20,682 | **62%** |

来源分别是：习语那条 `senses[].definition`（`◘ 短语 • 英文解释`）配同一个 sense 的 `translation`；
多词词条本身在牛津里有自己的词条，直接取它的中文；搭配靠 `collocation_translations`。
精简 ECDICT 里**没有**这些短语（抽查 5 条全部落空），所以词组释义只能从牛津生成时带上，或者运行时另有来源。

### 词组库：清洗 + 释义 + 例句（2026-10-14 第六次补充，已落地）

用本地 Ollama（`qwen3.5:4b`，热起来 0.1~0.4 秒/条）跑了一遍
`tools/build-phrase-meaning.mjs`，产物直接写进 `public/wordbooks/`，随着安装包离线可用：

| 词组库 | 原条数 | 现在 | 判据 | 释义 | 例句 |
| --- | --- | --- | --- | --- | --- |
| 固定习语 | 3,091 | **3,091**（全留） | 牛津 IDIOMS 原文 | 3,091 | 3,091（全部生成） |
| 常见搭配 | 20,682 | **715**（3.5%，严档） | 固定搭配、字面猜不出、雅思用得上 | 715 | 715（全部生成） |
| 多词词条 | 7,250 | **997**（14%） | 常会遇到 + 字面猜不出 | 997 | 997（牛津自带 189 + 生成 808） |

三个库合计 **1.4 MB**（原来 0.6 MB）。例句按"不低于雅思 6.5"写：先生成英文，再单独翻中文
（一次生成中英两句时，中文质量不稳，实测出现过"是福在 disguise 之中"这种漏英文的毛病）。
判分与例句进度写在 `data/phrase-ai/`（已 gitignore），中断可续跑；`node tools/build-phrase-meaning.mjs --write`
可以只用已有进度重写 JSON。

**踩到的坑**：进度文件每分钟往项目里追加几百行，Vite 的 watcher 被它刷爆——每个模块的转换慢到 2.2 秒，
页面几十秒都挂载不出来。已在 `vite.config.ts` 里把 `data/phrase-ai/**` 加进 `server.watch.ignored`。

词组的朗读按用户要求**只走系统语音**：词组卡不取音频、也不显示音标行，朗读前把 `sth` / `sb` 换成
something / somebody（否则系统语音会念字母）。

### 释义排版定稿（2026-10-14 第七次补充，已进产品代码）

线上那版把义项一条一行、还做了"第一条大、其余小"，用户看过之后要求：**字号统一、左对齐、不要序号、
每个词性最多 4 条**。设计稿在 `design-previews/word-study-meaning-preview.html`
（截图 `evidence/study-meaning-preview.png`），里面放了 `happen`、`low`、`state` 的词卡、
一张词组卡和"改之前"的对照；产品里的样子见 `evidence/study-app-meaning-rows.png`。

最终规则：

| 项目 | 做法 |
| --- | --- |
| 分组 | 一行一个词性；词性只在**行首固定宽度的一列**出现一次 |
| 条数 | 每个词性取前 **4** 条义项 |
| 字号 | 全部 16px（正文），不再有"第一条大、后面小" |
| 对齐 | 左对齐，不要序号 |
| 标点 | **不动词典原标点**：义项之间用 `；` 连接，每条义项内部的逗号/分号保持原样（不做模型分组——用户明确说不改标点，工程量太大） |
| 卡片 | 取消「展开全部」和 `+N 条`；卡片内部滚动保留，底部按钮依旧不动 |
| 词性标签 | 卡片左上角原来那个词性标签删掉（行首已经写了，重复） |

注意：每个词性只显示前 4 条是**主动截断**（`run` 这种词一个词性有 33 条义项），这是当前版本的取舍。
