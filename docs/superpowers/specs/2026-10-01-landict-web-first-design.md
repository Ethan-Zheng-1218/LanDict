# LanDict 网页优先界面开发设计

## 目标

先在浏览器中完成 LanDict 的可视化界面和基础交互，让用户可以直观看到并评价产品设计；确认界面和交互满意后，再把同一套前端代码放入 Tauri，打包为 Windows 本地应用。

这里的“网页”是开发和预览方式，不代表最终产品要做成在线网站。

## 当前主线

以后以 `C:/Users/Ethan/Desktop/floders/vibe/Pudict` 为项目主目录，以根目录的 Vite + React 前端为主线：

- `src/`：未来网页预览和 Tauri 桌面应用共用的 UI 与交互代码
- `src-tauri/`：后续 Windows 应用壳，当前只保留基础结构
- `web/`：旧的 Next.js 实验目录，暂不继续开发

网页阶段优先保证可以通过浏览器启动、浏览和操作；桌面打包阶段尽量不重写 UI。

## 第一阶段范围

### 页面

- 查词首页：搜索框、英文内容推荐、最近学习记录
- 单词详情：单词、音标、英式/美式发音入口、释义、例句、加入生词本
- 生词本：已收藏单词列表、基础筛选和查看详情
- 阅读：先提供页面骨架和示例文章入口
- 背单词：先提供页面骨架和学习入口
- 学习记录：展示示例统计和最近活动
- 设置：展示词典、翻译、发音和应用设置的分组入口

### 交互

- 导航可以在页面之间切换，并明确显示当前页面
- 输入英文单词后使用本地假数据展示详情
- 输入句子或段落时展示翻译模式的占位结果
- 发音按钮先使用可替换的本地演示行为，不绑定供应商
- 加入生词本和查看生词本使用浏览器本地状态
- 空状态、加载状态和错误状态有清晰的界面表现

## 暂不实现

- 真实词典、翻译和 AI API
- SQLite 或其他持久化数据库
- API Key 安全存储
- 真实语音播放、语音识别和语音合成
- 完整阅读器、间隔重复算法和 AI 对话老师
- 用户账号、云同步和在线部署

## 架构原则

- UI 组件、页面状态、示例数据和未来服务接口分开
- 页面不直接依赖具体 API 供应商
- 先定义可替换的查询、翻译、发音和生词本接口；第一阶段使用本地演示实现
- 网页预览和 Tauri 应用共享 `src/`，避免为桌面端重新制作界面
- 每个小功能先写行为测试，再实现，再运行完整测试

## 验收标准

网页阶段完成后，代码小白可以在 VS Code 中启动项目，并在浏览器看到一个完整、清晰、可点击的英语学习工作台原型；用户可以从查词首页进入单词详情、收藏单词、查看生词本并切换其他模块。页面风格、布局和交互可以在进入真实 API 和桌面打包前独立评审。

1. 建立网页版本的可靠基线和启动说明。
