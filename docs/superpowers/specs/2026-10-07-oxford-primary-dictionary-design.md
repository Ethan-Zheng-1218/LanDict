# LanDict 底层内置词库更换设计（牛津为主 + 精简 ECDICT 兜底）

本文是「更换底层内置词库」的设计文档，供实现前评审。当前只有设计与核实产物，未修改任何应用代码。

## 一、为什么要做

发给朋友的安装包中，与词库相关的部分目前是 812 MiB，而这个大字库里真正被使用的只有中文释义一层。

已核实的现状：

- 打包配置只映射了一个词库文件 data/ecdict-sqlite-28/stardict.db，851,288,064 字节（约 812 MiB）。
- 牛津高阶双解第七版与 Merriam-Webster's Collegiate 2015 两份词典只存在于开发目录。它们仅被开发服务器的查询中间件读取，从未进入安装包，因此安装版拿不到牛津的例句、搭配，也拿不到韦氏的美音音频。
- ECDICT 被剔除后，源码中依赖它的功能共四条链路：查词释义、中文反查、词形还原、阅读页词族高亮。

本次要达成的目标：

1. 安装包中词库相关体积从 812 MiB 降到约 40 MiB。
2. 中文释义改用牛津高阶双解：学习者向释义、真实例句、常见搭配。
3. 上述四条链路完整迁移，不出现功能缺口。
4. 音标与音频完全不动：不改来源、不改优先级、不改解析、不改播放。

## 二、实测数据

以下数字均由本次核实直接测得，不是估算。

| 项目 | 实测值 |
| --- | --- |
| 现用 ECDICT 词条总数 | 3,402,564 条（851,288,064 字节） |
| 精简筛选后保留 | 58,331 条（10.1 MiB，占 1.7%） |
| 牛津词条总数 | 42,481 个关键词，按小写归并同形条目后 42,338 条 |
| 牛津带义项中文翻译的词条 | 39,997 条（81,753 条义项翻译行，占 94.1%） |
| 牛津抽出的中文反查词条 | 102,485 条（含义项位置；只收前三个非成语义项） |
| 牛津变形指向（pt of / pl. of） | 431 条 |
| 牛津转为紧凑 SQLite 后 | 25.8 MiB |
| CC-CEDICT 原始数据 | 125,215 条（9.40 MiB，CC BY-SA 4.0） |
| CC-CEDICT 转成反查索引后 | 98,647 个中文词，7.00 MiB |
| 精简 ECDICT 加牛津加反查索引合计 | 约 42.8 MiB |

精简 ECDICT 的保留规则沿用插件已在使用的口径：Collins 标记大于 0，或牛津收录，或 BNC 词频 1-50,000，或词频序号 1-50,000，再过滤完整英文词与空中文释义。结果：

- BNC 词频前 20,000 词：保留 100%
- BNC 20,001-50,000 词：保留 100%
- 其余无词频排名词条：仅保留 0.4%（12,888 条）
- 保留行中缺中文释义的数量：0

## 三、需要纠正的一个预期：覆盖率是持平，不是提升

本方案的卖点是内容质量，不是覆盖面。核实结果如下，请按此预期验收：

| 词频区间 | 现状（完整 ECDICT） | 仅牛津 | 方案（牛津加精简库兜底） |
| --- | --- | --- | --- |
| BNC 前 3,000 词 | 100% | 97.0% | 100% |
| BNC 前 20,000 词 | 100% | 87.1% | 100% |

精简库本身已完整覆盖高频区，牛津补不上这一层的缺口；牛津单独的覆盖率反而更低，短板集中在专有名词（America、York、Leeds）、月份缩写（Oct、Nov）、部分派生素（affordable、agricultural、automatically）。这正是必须保留精简 ECDICT 兜底的原因。

真正的收益是释义质量与例句搭配，这一点在验收标准中单列。

## 四、选定方案

牛津为主加精简 ECDICT 兜底，另加一份汉英词典专管中文反查。牛津负责中文释义、例句、搭配；精简 ECDICT 负责兜住牛津不收的词与词形还原；中文反查改用 CC-CEDICT。总量约 44 MiB。

被否决的备选：

- 只精简 ECDICT：改动最小、零行为变化，但内容质量没有提升。
- 只换牛津：体积更小，但专有名词与派生素出现明显缺口，且词形还原缺少兜底数据。

## 五、架构决策

### 5.1 构建期生成 SQLite，运行期不引入 MDX 解析

桌面端查询层是 Rust，为 812 MiB 的 SQLite 写好了原生查询。若改为运行期直接读 .mdx，Rust 侧需要新增 MDX 解析依赖，同时现有解析依赖 @runer-hq/mdict 为 GPL-3.0，引入范围需要单独评估。

因此：在构建期把牛津 .mdx 解析并落成与现有结构一致的 SQLite，运行期 Rust 仍然只用 SQLite，查询层结构与打包方式都不变。构建脚本在开发机执行，生成物随包发布。

### 5.2 策略与原子查询分离

现有架构中 ECDICT 查询逻辑在开发服务器（Node，server/ecdict.ts）与桌面端（Rust，desktop_queries.rs）各写了一份。若牛津接入再照抄一遍，候选词生成、优先级合并、反查过滤都要维护两份，是本次最大的工程风险。

因此把职责切开：

- 策略层（一份，共享 TypeScript）：输入规范化、候选词生成、牛津与 ECDICT 的优先级合并、反查结果过滤与排序、词族合并。放在前端共享模块，开发版与桌面版共用。
- 原子查询层（各一份，逻辑极薄）：按给定词返回牛津条目、ECDICT 条目、中文反查命中、词形原形。开发版是 Node 中间件，桌面版是 Rust 命令，两者只差几行 SQL。

为减少调用往返，原子查询接受批量词表：策略层一次把「原词加全部候选原形」发过去，一次拿回全部结果。悬浮查词因此仍是一次调用。

### 5.3 中文反查不复用牛津的英汉数据

牛津是英汉词典，从英文出发。把它倒过来查中文，受它的用词习惯摆布，算法补不回来。实测证据：牛津的 abandon 词条共 6 个义项，主要中文对应词是「离弃、遗弃、抛弃」，「放弃」只出现在第 3、4 个义项里。而 relinquish、waive、forgo 的第 1 个义项就是干净的「放弃」。因此查「放弃」时 abandon 必然排在它们后面，这不是排序可以修复的问题。

改用一份真正的汉英词典 CC-CEDICT 作为反查主数据源，牛津的中文索引降为补充。CC-CEDICT 查「放棄」给出的正是 `to renounce; to abandon; to give up`，与商业汉英词典一致。

### 5.4 音标不从新库读取

新生成的牛津库不存音标字段。音标继续走现有链路（pronunciationService.ts 的优先级、牛津 IPA 解码 queryOxfordPronunciation、韦氏音频、在线兜底、系统 TTS），一行不改。不把音标写进新库，是为了避免将来有人顺手从新库取音标，绕开既有优先级。

## 六、数据产物与表结构

### 产物 A：data/oxford-sqlite/landict-oxford.db（新增，约 31 MiB）

```sql
CREATE TABLE entry (
  word         TEXT PRIMARY KEY COLLATE NOCASE,  -- 检索键
  headword     TEXT NOT NULL,                    -- 展示用原始拼写
  pos          TEXT NOT NULL DEFAULT '',         -- 首个词性
  senses       TEXT NOT NULL,                    -- JSON 数组，见下
  collocations TEXT NOT NULL DEFAULT '[]',       -- JSON 字符串数组
  examples     TEXT NOT NULL DEFAULT '[]'        -- JSON 数组
);

-- senses:   [{"pos":"noun","definition":"a small animal ...","translation":"猫"}]
-- examples: [{"pos":"noun","text":"cat food","translation":"猫食品"}]

CREATE TABLE hanzi (   -- 中文反查索引
  term TEXT NOT NULL,  -- 归一化后的中文片段
  word TEXT NOT NULL   -- 指向 entry.word
);
CREATE INDEX idx_hanzi_term ON hanzi(term);

CREATE TABLE lemma (   -- 牛津自带的变形指向，如 ran 指向 run、men 指向 man
  form TEXT PRIMARY KEY COLLATE NOCASE,
  base TEXT NOT NULL
);
```

抽取口径：义项中文翻译取自词条 HTML 中 color=#FF5000 标记的段落（每条义项一行）；例句翻译取自 color:#039 段落。同一份 HTML 已被 server/oxford.ts 解析例句与搭配，本次把它的解析结果完整落库，不再只在开发服务器可用。

### 产物 B：data/ecdict-sqlite-28/stardict-slim.db（新增精简版，约 10.1 MiB）

沿用现有六列（word、phonetic、definition、translation、pos、exchange），并在末尾追加 bnc 与 frq 两列。追加是必需的：中文反查的排序规则要用 bnc 当英文词频（第七节 7.2），而原库的这两列必须随精简库一起保留。全仓库没有任何 `SELECT *`，现有查询都用具名列，因此追加列不会影响 `server/ecdict.ts` 与 `desktop_queries.rs` 的语句。

**路径改为独立文件名而非原地替换。** 实测本机有外部程序（杀毒或索引服务）长期持有 `stardict.db` 的句柄，改名与覆盖都会返回 EBUSY，沙箱内外都一样。改用 `stardict-slim.db` 既绕开这个问题，也不会误删 812 MiB 的原始数据。完整库保持原样留在 `data/ecdict-sqlite-28/stardict.db`，确认安装版一切正常后可由使用者自行删除。

**一处必须记录的覆盖变化：** ECDICT 的词频只标在原型词上，`ran`、`went`、`mice`、`knives`、`walked` 这类变形词的 bnc 与 frq 都是 0，因此会被精简剔除，不再有自己的条目。查这些词时改由 exchange 索引落到原型（`ran` 得到 `run`），这正是第七节 7.3 词形还原要接手的工作。`server/ecdict.test.ts` 里原本断言「变形词有自己的条目」的用例已按此改写，并新增用例记录这条边界。

### 产物 C：data/dictionary-build.json（构建记录，体积可忽略）

记录各产物的源文件哈希、生成时间、保留行数、筛选口径。用于确认产物与源码一致，以及回退时比对。

### 产物 D：data/cedict-sqlite/landict-cedict.db（新增，约 1.5 MiB）

```sql
CREATE TABLE cedict (
  term  TEXT NOT NULL COLLATE NOCASE,  -- 简体中文词
  gloss TEXT NOT NULL                  -- 英文对应词，一条一行
);
CREATE INDEX idx_cedict_term ON cedict(term);
```

由 CC-CEDICT 原始文本转出：按行解析 `繁体 简体 [拼音] /英文/英文/` 格式，只取简体列，按分隔符拆出英文对应词，去掉 `to ` 前缀与括号限定语，保留英文单词与不超过三个词的短语。原始文件不含 gzip 压缩，9.40 MiB 纯文本。

实测索引为 98,647 个中文词、7.00 MiB，比只保留单个英文单词的版本（55,963 词、1.54 MiB）大 5.5 MiB，但质量明显更高：`放弃` 因此能同时给出 abandon 与 give up，`睡觉` 能给出 sleep 与 go to bed。这些短语正是商业汉英词典会列的答案，值得这 5.5 MiB。

原始文本需要随仓库或构建流程保存一份，并保留下载来源与许可说明。

## 七、四条查询路径的改动

### 7.1 查词（英译中）

优先级：牛津精确命中，其次牛津经词形还原命中，其次精简 ECDICT 精确命中，其次精简 ECDICT 经词形还原命中，最后未收录。

牛津命中时，meanings 取牛津义项翻译（按词性分组），examples 与 collocations 取牛津，meaning 汇总字段取牛津译文。ECDICT 命中时的展示与现状一致。空结果的提示文案不变。

### 7.2 中文反查（中译英）

优先级：CC-CEDICT，其次牛津 hanzi 索引，最后精简 ECDICT 反查。三个来源按顺序合并去重，取前 N 条。

排序规则（按优先级依次比较），由实施阶段的实测选定：

1. 来源顺序：CC-CEDICT 优先于牛津 hanzi 索引，精简 ECDICT 最后兜底。
2. 英文词频，取精简 ECDICT 的 bnc 列，序号小者优先；多词短语没有词频，取中位值 5000。
3. 义项位置：牛津来源中同一词条内该中文出现的义项序号，小者优先。
4. 字母序，保证结果稳定。

**词频不能放在第一优先级。** 牛津的 get、give、back 各有上百个义项，某个次要义项里带过「放弃」，而它们的词频（41、71、105）远高于 abandon（2057）。实测词频优先时，「放弃」的前六条是 get、give、give、back、back、part，完全不可用。来源优先把这类噪音压到 CC-CEDICT 之后，首条才回到 abandon。

**短语也不能一律垫底。**「睡觉」的正确答案是 go to bed、「生气」是 get angry / be furious，它们在 ECDICT 里没有词频。若按无排名垫底，这些词会被 vitality 之类的冷门单词挤掉，所以给短语一个中位词频。

实测十条查询的效果：放弃→abandon、跑步→run、提高→raise、睡觉→sleep、银行→bank、猫→cat、电脑→computer、骚扰→disturb（harass 在第三条）、生气→be furious、美丽的→fair。

已知不足：「猫」的第三条是 modem。CC-CEDICT 确实收录了「猫」的口语义「调制解调器」，而它的词频 9165 高于 feline 的 23868，靠现有信号压不下去。

**中文索引只收前三个非成语义项**（建索引时的 `MAX_INDEXED_SENSE = 2`）。牛津的义项按常用度排序，越往后越是专门的用法，词往往只是在那里被提到一次。实测：`equal` 的第 5 个义项里带过「无敌」，收录它会让查「无敌」的人看到 equal；`get`、`give`、`back` 各有上百个义项，同理。加上这条限制后牛津索引由 143,446 条降到 102,485 条：「无敌」的结果回到 a paragon、without rival、unequalled，而「放弃」「骚扰」「猫」「提高」「睡觉」「生气」全部保持正确。

**每条候选独占一行，后面跟上它自己的中文释义。** 光给英文词读者分不清这些近义词，所以候选定下来之后会用一次批量查询回查它们各自的中文，格式为 `abandon　放弃`（全角空格分隔）。界面样式的 `white-space: pre-line` 让换行原样显示，无需改样式。

返回条数上限为 6 条（第六节之外的展示决策，见第十四节）。

不再受现有「1 到 2 个汉字」的限制，可支持任意长度中文词。

### 7.3 词形还原

改为「规则候选加不规则表加词典验证」三段式，不再依赖 ECDICT 的 exchange 字段：

- 规则候选：沿用并扩展 src/features/reading/wordMatch.ts 已有的 baseFormCandidates，补充 -ly、-er/-est、-ness、-ment、-ation 等派生后缀。这些规则必须只在候选经过词典验证后才生效，避免出现 worker 还原成 work、computer 还原成 compute 这类错还原。
- 不规则表：手工维护约 200 条常见不规则变形（ran/run、went/go、children/child、better/good 等）。
- 词典验证：候选依次在牛津、精简 ECDICT 中验证，取第一个命中者。

实测该组合在 BNC 前 3,000 词的覆盖率为 97.0% 提升到 97.5%，配合精简库兜底后高频区为 100%。

### 7.4 阅读页词族高亮

词族数据源由 ECDICT 的 exchange 字段改为：牛津 lemma 表、不规则表与规则候选三者合并。

顺带修正一处现状：wordFamilyStore 请求的是相对地址 /api/word-family，桌面版没有开发服务器，该请求必然失败，所以安装版阅读页目前只有规则层在生效。迁移后桌面版改为走批量原子查询，高亮能力反而比现在更完整。

## 八、硬边界：不动的部分

以下文件与行为在本设计中明确不改动，实现阶段如有冲突需停下确认：

- src/features/translation/pronunciationService.ts：音标与音频来源的整套优先级逻辑
- server/oxford.ts 的 queryOxfordPronunciation 与 parseOxfordPronunciation（IPA 解码）
- server/merriamWebster.ts：音频 ID 映射与 MP3 地址拼接
- src/features/reading/speech.ts：朗读与语音选择
- 系统 TTS 兜底行为

必须记录的一处非逻辑影响：精简 ECDICT 会把「ECDICT 音标」这一层兜底池从 340 万条缩到 5.8 万条。代码不变，但对超出该范围的生僻词会少一层音标兜底。这些词同时也没有中文释义，实际影响有限，但不作为零影响处理。

## 九、打包与体积

src-tauri/tauri.conf.json 的 resources 由单条改为两条：精简 stardict.db 与 landict-oxford.db，映射到 dictionaries 目录下。牛津的 .mdx/.mdd 原件与 data/ecdict-sqlite-28 的完整库都不进入安装包。

Rust 侧词库路径解析需同时覆盖开发路径与 resource_dir 路径，保持现有「开发缺文件时回退到仓库路径」的行为。

预期安装包中词库部分由 812 MiB 降到约 44.5 MiB。最终数字以实际构建产物为准，不直接推算。

## 十、版权

这是本方案唯一无法靠工程手段解决的问题，需要在实施前确认。

- ECDICT 为 MIT 许可，随附 pudict-extension/data/ECDICT-LICENSE.txt，可自由分发。
- CC-CEDICT 为 CC BY-SA 4.0 许可，明确允许分发；使用时需注明来源，并让由它改造出的索引以相同许可开放。软件代码本身不受该许可约束。
- 牛津高阶双解与 Merriam-Webster's Collegiate 均为商业版权词典。把它们打进安装包发给朋友，性质上是再分发受版权保护的内容。

CC-CEDICT 是本方案中许可最干净的一份反查数据，因此中文反查不再依赖牛津的商业数据。

本文不替使用者做法律判断，但要求在设计评审时明确目标分发范围：若仅限自己与本机使用，风险可控；若确要发给朋友，需要另行决定是否只发布不含牛津数据的版本，或改为引导用户自备词典。

## 十一、风险与回退

| 风险 | 应对 |
| --- | --- |
| 牛津条目解析出现错位，释义或例句串行 | 构建脚本产出后抽样对比原始 HTML，并在产物记录中写入解析统计 |
| 精简库筛选口径不当，常用词意外丢失 | 用 BNC 前 50,000 词做回归断言，保留率必须为 100% |
| 策略层与原子查询层职责再次混淆 | 原子查询只允许返回数据，不做优先级判断；优先级判断只存在于共享 TypeScript |
| 安装版词库路径解析失败 | 保留现有开发路径回退分支，并在验证阶段实际安装后确认加载 |
| 版权问题导致方案不可用 | 设计上把牛津产物作为独立文件，可单独移除而不影响精简 ECDICT 与其余功能 |

回退方式：本次全部改动集中在新构建脚本、新产物文件与查询策略层。完整 ECDICT 与牛津原件在实施期间保留在 data 目录下，切换到旧行为只需恢复 tauri.conf.json 的 resources 单条映射并回滚策略层。

## 十二、验证范围

按项目 AGENTS 规则，本次涉及数据层与打包配置，属于公共改动，提交前需运行一次全量测试。

针对本设计的专项验证：

1. 构建产物断言：精简库 BNC 前 50,000 词保留率 100%；牛津库词条数 42,338；牛津中文索引词条数不少于 140,000；CC-CEDICT 中文词数不少于 90,000。
2. 查词回归：对 BNC 前 3,000 词逐个查询，命中率与设计一致，全部返回中文释义。
3. 词形还原回归：固定一组变形词（ran/run、went/go、children/child、better/good、taking/take、studies/study）断言还原结果。
4. 中文反查回归：固定一组中文（放弃、跑步、提高、睡觉、银行、猫）断言首条命中，其中「放弃」首条必须是 abandon。
5. 音标与音频回归：确认英式与美式音标文本、音频来源标记与改动前完全一致。这是本设计的硬边界，必须逐项比对。
6. 安装版实测：实际安装后确认词库加载、查词、反查、阅读页高亮均可用。

## 十三、分阶段实施

1. 构建脚本：产出 landict-oxford.db、精简 stardict.db、landict-cedict.db、构建记录，并附产物断言。
2. 策略层：抽出共享 TypeScript 模块（候选词生成、优先级合并、反查过滤），保持行为与现状一致，此阶段不接入牛津。
3. 来源切换：接入牛津条目，开发服务器与桌面端同时改走批量原子查询。
4. 词形还原与词族：接入不规则表与新规则，替换 ECDICT exchange 依赖，补齐阅读页桌面端高亮。
5. 打包与收尾：更新 tauri.conf.json 与 Rust 路径解析，做安装版实测，确认体积。

每个阶段独立提交，便于回档。

## 十四、已确认的决定

1. 精简 ECDICT 的筛选口径沿用现有 Collins 标记、BNC 5 万、词频 5 万的标准，不放宽。理由：使用者主要查常见词，生僻词不值得为它们撑大安装包。
2. 牛津与精简 ECDICT 同时命中时，释义、例句与搭配一律以牛津为准。
3. 中文反查返回条数上限为 6 条。理由：排序存在已知短板，6 条比 4 条多留两点容错；实测「骚扰」的正确答案 harass 排在候选第 1，但「放弃」一类仍需 CC-CEDICT 补位。
4. 分发范围为自用与身边朋友。CC-CEDICT 的许可负担已由它自身的开放许可解决；牛津与韦氏的版权问题按第十节记录，使用者已知悉。
