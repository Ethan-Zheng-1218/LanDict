# LanDict Windows 安装器技术可行性检查

检查日期：2026-10-08。范围：第一阶段技术检查；尚未实现、构建或运行新安装器。修改前的本地 Git 检查点为 `9def170`，前一个产品提交为 `1c28d37`。未执行 push。

## 结论与需要确认的决定

建议保留 **Tauri 2 + NSIS 安装引擎**，使用自定义 NSIS 模板，加一个安装器专用的 **Rust / Win32 原生绘制模块**。模块在安装窗口内分层绘制图片、动画、文字和进度；NSIS 继续负责文件、WebView2 检测、注册表、快捷方式、重复安装和卸载。无需修改应用主体或新增 WebView 安装前端。

这条路线在接口和系统能力层面可行；本轮没有原生运行样例，不能据此宣称动画流畅、视觉验收或真实安装测试通过。下一步应先生成可运行的原生 EXE 预览，用真正的 NSIS 文件解压驱动进度，并验证解压期间动画继续播放，再接正式应用 payload。

必须确认两项：

1. 是否采用自定义模板和独立原生绘制模块。默认 NSIS 换图片、颜色或仅加安装钩子，无法合理覆盖这套完整布局和动画。新增模块属于安装器内部结构调整，不是更换软件框架。
2. 是否以真实进度为准，让条长与百分比一致。c.png 标为 0%，条却约填充六成；d.png 的条长与 98% 也不完全对应。不能同时逐像素复制这些状态和保持真实、成比例的进度。建议保留条的位置、尺寸、颜色和圆角，仅由实际引擎进度决定填充长度；0% 时空条，全部成功后才为 100%。如果这一差异不可接受，应先明确一致的进度参考状态。

用户最新明确要求：标题栏左上角软件图标改用项目根目录 `icon.png`；中央品牌旁的小羊、奔跑小羊、完成小羊保持原形象。产品配置实际名称为 LanDict，因此不把本次安装器工作变成 PuDict / LanDict 重命名。

## 视觉实现边界

**小羊逐帧动画：可实现，需验证软边与节奏。** 原生绘制模块预先解码六帧，在 UI 消息循环中定时选择帧；按共同落脚基准和帧姿态摆放，避免用整体上下抖动代替腿部关键帧。完成姿态从 e.png 中的既有角色区域取得，不生成新形象。六帧数量允许循环，但自然程度必须看原生播放后再判断。

**地球缓慢旋转：可实现二维正面滚动。** 使用 b.png 的完整地球，围绕其圆心旋转，再由前景云遮挡下半球，不改变大陆和水彩线条。这里只有正面圆形画作，没有球面展开纹理或地球各面素材；真实三维自转不能保持画作逐像素不变。c/d/e 的大陆位置变化可以用同一圆形画作在画面平面内旋转解释，建议采用这一方式；若用户意图是三维绕竖轴旋转，应先确认且不能擅自补画背面。

**云朵层次：可实现。** 前景云、浮动云、地球、小羊按各自层序合成，不能用整幅 c/d/e 静态截图替代场景。已有云层允许恢复基准尺寸的外观，但缺少高分辨率原始分层；在 150% / 200% 缩放下是否足够清晰仍需验收，不能预先保证。

**文字和 Logo：可独立实现，原始字体缺失。** 中央羊、字标、勾号保留独立图层；状态、标题和百分比使用独立文字绘制或原生控件。现有字标只有 198 × 61，放大精度受限。状态字体没有源文件或指定字体信息，必须根据参考对齐字形和指标后进行视觉比对，不能声称已做到完全相同。

**窗口：布局可自定义，系统外框不能默认保证一样。** c/d/e 含不同大小的外部留白和截图阴影，不能把整张 PNG 的大小直接当窗口大小。按边框估算，实际窗口约 730 × 583，宽高比约 1.25；此尺寸是参考像素估计，不是已确认的原始 DIP 尺寸。后续先统一裁出窗口区域再确定坐标。保持原比例，不采用旧演示的 764 × 660 布局，也不新增底部操作栏、第二行介绍文字或安装目录输入。

严格控制标题栏颜色、按钮位置和边框时，应自绘标题栏并保留真实拖动、关闭等系统行为；默认 Windows 标题栏会随系统版本、主题和 DPI 改变。无论选择哪种，都须在 100% / 125% / 150% / 200% 和跨屏 DPI 变化下测试，不能以单一浏览器缩放证明正确。

参考未定义安装前确认、路径修改、取消错误和安装后启动交互。实现时这些流程不能擅自挤入额外底栏；如需新增可见内容，应提交具体布局给用户确认。可以先预览已定义的安装中和完成状态。

## 真实进度和动画并发

保留真正的 NSIS InstFiles 安装页及其进度控件。自定义绘制读取该控件的位置和范围，或监听引擎发给它的进度消息；条长和百分比来自同一个引擎值，绝不按动画时钟增长。成功状态来自安装成功事件，文件、卸载入口和所选快捷方式全部完成后才显示 100%。失败或取消不得显示成功。

NSIS 源码显示，InstFiles 页把 `install_thread` 放入工作线程，UI 线程可以继续处理绘制。引擎的默认位置按安装指令执行推进，范围通常为 0–30000。因此这一进度是真实引擎进度，但不是逐字节或剩余时间：复制单个大词典时可能暂时停住，分支和外部 WebView2 安装也需要单独状态处理。不能人为缓动到尚未完成的位置，更不能为展示长动画增加安装等待时间。

原生绘制仅处理 UI 线程中的图像、时钟和引擎进度；定时器不能在安装期间反复回调 NSIS 脚本、同时访问脚本栈和变量。预解码图片，重复使用绘图资源，安装线程和渲染线程之间仅传递进度及结果。需实测 UI 线程阻塞、消息响应和资源释放。

源码依据：[NSIS UI 工作线程](https://github.com/NSIS-Dev/nsis/blob/master/Source/exehead/Ui.c)、[NSIS 进度计算](https://github.com/NSIS-Dev/nsis/blob/master/Source/exehead/exec.c)、[NSIS ChangeUI 必需控件](https://nsis.sourceforge.io/Docs/Chapter4.html#4.8.1.8)。

旧方案提出 Windows 动画控件 AVI 播放。系统控件只支持无音轨、未压缩或 RLE8 AVI；RLE8 颜色限制不适合原图柔和纹理，未压缩长周期画面则体积大，而且不能方便地独立调整羊和地球周期。ComCtl32 v6 在 UI 阻塞时也不会继续动画。故不把 AVI 作为主方案，更不把它作为已通过的原生播放能力。

依据：[Microsoft 动画控件限制](https://learn.microsoft.com/en-us/windows/win32/controls/animation-control-overview)。

## 免费开源备选与维护成本

**NSIS 自定义模板 + 安装器专用原生绘制模块（建议）。** 沿用项目支持的安装引擎和 Rust 工具链，Windows 内置绘图 API 支持旋转、alpha 合成和独立文字。无需新增运行环境。主要维护成本是 NSIS 模板跟随 CLI 版本、32 位插件接口、DPI 和 Windows 窗口行为。先用最小原生预览验证，未通过前不承诺完成。NSIS 为免费开源，许可证见 [官方说明](https://nsis.sourceforge.io/Docs/AppendixI.html)。

**Inno Setup。** 官方提供 `CurInstallProgressChanged`，可观察文件提取、快捷方式和注册表的真实进度；窗口可通过 Pascal 脚本定制。但水彩 alpha 图层、旋转和动画依然需要实际绘制能力，并不会仅换引擎就自动实现。Tauri 默认不生成 Inno 安装器，需维护自己的文件清单、升级识别、WebView2、卸载和快捷方式逻辑，因此迁移成本高于保留 NSIS。源码公开；官方目前对商业用户有购买许可证的请求，不能笼统承诺所有使用场景都无成本。见 [进度事件](https://jrsoftware.org/ishelp/topic_scriptevents.htm)、[源码项目](https://github.com/jrsoftware/issrc)、[当前商业授权说明](https://jrsoftware.org/isorder.php)。

**WiX / Burn 自定义 Bootstrapper Application。** 支持把 UI 与包执行引擎分开；可以构建自定义原生界面。但需要额外包链、Bootstrapper Application、升级和引擎事件处理。现有 Tauri WiX MSI 配置也不能直接提供这幅动态界面。对本任务没有足够收益来抵消维护成本，不优先采用。见 [Burn 官方架构文档](https://docs.firegiant.com/wix/tools/burn/)。

**独立 WebView / Tauri 安装前端。** 图层动画方便，但前端在 WebView2 尚未安装时自身可能无法显示，还需解决安装引擎通信、双进程错误和生命周期。它是更大的结构调整；不因为现有 HTML 演示可播放就选择这条路线。

以上成本比较是基于本项目接口和新增责任的工程判断，不是对各方案做过性能测试的结论。当前没有证据表明 NSIS 必须更换。

## 用户数据与后续验收

应用目前使用浏览器 localStorage 保存学习数据；Tauri 标识符关联其 WebView 数据目录。保持 `com.pudict.desktop` 和原数据路径，不添加学习数据迁移或清理。CLI 2.12.0 的 NSIS 卸载模板包含一个可选“删除应用数据”分支；为符合本任务要求，自定义卸载不得启用这个分支。卸载仅删除安装文件和属于该安装的注册信息、快捷方式，不递归删除用户数据。

真实验证应在干净 Windows VM / Sandbox 中进行，并有独立用户配置，而不仅是宿主机上的不同安装目录。本轮未发现 WindowsSandbox.exe 或 PATH 中的 VirtualBox / Hyper-V 启动工具；这不能证明虚拟化组件绝对不可用，但尚没有可直接使用且已验证的隔离环境。不得在当前用户的现有安装上试装卸载来冒充隔离测试。

确认方案后的验收顺序：

1. 原生 NSIS 预览：真实文件解压、真实进度、无业务应用写入；观察动画并发和不同 DPI，截图与规范化参考比较。
2. release payload：正式应用和三份词典；测试首次安装、启动和资源读取、开始菜单及桌面快捷方式、卸载入口。
3. 重复安装及升级：识别既有目录和注册信息，应用运行时合理提示，学习数据保留。
4. 卸载：验证程序及安装资源删除，学习数据保留；同一干净环境再次安装并启动。
5. 缺少 WebView2、写入失败及取消：真实错误状态、无假成功，动画不会决定安装结果。

本轮仅完成配置读取、源接口检查、素材尺寸 / 格式 / 哈希检查、部分云层 alpha 抽样和工具位置检查。未执行安装、启动、卸载、真实安装窗口截图、DPI 实测或性能测试。没有新安装 EXE 可交付；旧 HTML 也不计为任何安装验证结果。
